## Asset duplication audit

| Pair | Byte comparison | Runtime usage | Decision |
|---|---|---|---|
| src/brandFaviconData.ts ↔ public/favicon.png | Exact SHA-256 match | apiRoutes.ts embeds the PNG for fallback when ASSETS.fetch is unavailable; public file is served by the static asset layer | Keep both |
| src/botDescriptionImageData.ts ↔ public/bot-description-640x360.jpg | Exact SHA-256 match | Same fallback pattern for the BotFather description image | Keep both |
| src/ogImage.ts ↔ public/og-image.jpg | Not byte-identical | Embedded JPEG/PNG buffers back API fallback routes; public JPEG is the canonical static OG asset | Keep both; not an exact duplicate |

The favicon and bot-description payloads are intentional duplicated representations, not dead assets. Removing either embedded source would break the no-static-binding fallback path. The Open Graph source also exposes distinct embedded PNG/JPEG data; its JPEG payload does not hash-match the public JPEG.

Other public assets are referenced by the landing page, manifest, admin page, or Worker static-asset binding. The Telegram gallery images are asserted in landing-page tests. No public asset was proven unused.

## Production vs non-production files

### Production runtime / deployment — retain

- src/**, including worker.ts, apiRoutes.ts, bot.ts, db.ts, storage.ts, image fallback modules, and route/page modules.
- public/** and wrangler.toml.
- migrations/**.
- package.json and package-lock.json (reproducible CI installation).
- deploy.sh, .github/workflows/ci-cd.yml, and environment/migration validation scripts used by CI or deployment.

### Build, test, and developer tooling — not Worker runtime, but retain

- tests/**, vitest.config.js, vitest.testdriver.config.js.
- .github/workflows/testdriver.yml, .github/workflows/codeql.yml, .github/dependabot.yml.
- eslint.config.mjs, tsconfig.json, validate-migrations.mjs.
- src/index.ts and its Node-only support modules are used by the local Node server scripts; they are not the Wrangler production entrypoint.
- scripts/generate-telegram-graphics.mjs is a developer asset-generation utility, not a Worker runtime dependency.

### Documentation / audit artifacts — no production bundle impact

- docs/**, including docs/seo-audit/**, are not imported by the Worker or included in the static asset directory.
- The SEO audit report is historical and includes claims that no longer match this checkout (for example, it reports missing OG/favicon assets that are present). Keep it as history, but use current implementation notes and live configuration as the source of truth.
- The CSVs, chart PNGs, repository maps, architecture notes, plans, and operations guides are documentation artifacts, not unused application source.

### Generated and local-only artifacts

- dist/ is generated by npm run build and ignored by Git.
- Local .env and SQLite database/WAL files are ignored; data/.gitkeep preserves the directory.
- Existing ignore rules already cover dependencies, Wrangler output, build output, test coverage, logs, and local databases. No tracked local database or build artifact was found.

## Safe cleanup decision

No tracked application source file, test, migration, deployment file, or public asset was proven safe to delete. The two exact asset pairs are required fallback copies. Documentation and audit files are outside the production bundle, but their non-runtime status alone does not make them disposable.

**Therefore this audit makes no destructive file removals.** Any future deletion should be a separate, narrowly scoped change with import/reference checks, route/fallback tests, and a successful Wrangler dry run.
